# Codeverta とインドネシア医療のデジタル化：電子カルテから SATUSEHAT 統合まで

医療のデジタル化は、クリニックが紙を使わなくなった時点で仕事が終わったかのように語られることがよくあります。しかし、実際はそれほど単純ではありません。

フォームを画面に変えることはプロセスの一部です。しかし、より難しい仕事はその後で発生します。患者データの重複を防ぎ、医師や看護師の流れを快適に保ち、在庫と処方を連携させ、検査結果を正しい履歴に紐づけ、義務付けられたデータを国のエコシステムに送信できるようにすることです。

ここで Codeverta が役割を果たします。私たちは医療施設が毎日使用するテクノロジーのレイヤーを構築する支援を行います。クリニックや病院の管理システム、電子カルテ、薬局、検査室、医療スタッフのスケジューリング、そして SATUSEHAT との統合準備に至るまでです。

その役割は明確です。保健省（Kementerian Kesehatan）は、国家医療データ交換プラットフォームとして SATUSEHAT を構築しています。Codeverta は医療施設と運用システムの側で活動します。日常の診療から生まれるデータを整理し、構造化し、安全にし、保健省の規定に従って交換可能な状態にします。

## 問題は単に「アプリケーションがない」ことではない

多くの医療施設では、実際にはアプリケーションは既に存在しています。受付はあるシステム、診察室は別のシステム、検査室は独自の記録、薬局や会計はまだスプレッドシートに頼っている。各部門は機能しているかもしれませんが、データが常に同じ言語で話しているとは限りません。

その結果は容易に予想できます：

- 患者は以前に提供したデータを何度も繰り返さなければならない；
- スタッフは一つの画面から別の画面へ情報を転記する；
- 医師は検査結果を確認するのが遅れる；
- システム上の在庫数と実際の棚の状態が一致しない；
- 経営レポートは何度か調整を経てようやく完成する；
- IT チームは相互運用性のためにデータ準備に苦労する。

私たちはヘルスケアプロジェクトを「どんな機能を作りたいか」という質問から始めません。最初の質問はもっとシンプルです。患者が来院してから帰宅するまで、誰が何を担当し、どのデータが変化し、どの時点でプロセスが最も滞るか？

その質問への答えがシステムの基盤となります。

_管理業務と診療業務を統合するクリニック管理システムのインターフェース例。_

## 基盤を築く：一つの流れ、一つの患者履歴

優れたヘルスケアシステムは、メニューの集まりのように感じられてはいけません。患者の旅に沿って動作する必要があります。

患者が登録するとき、システムは正しい識別情報を形成または検出します。患者が診察室に入ると、医師は関連する履歴を確認します。医師が処方箋や検査依頼を出すと、薬局と検査室は再入力なしでデータを受け取ります。診療が完了すると、臨床情報と取引は同じ受診に紐づいたままになります。

この原則をいくつかのレイヤーで適用しています。

### 患者登録と識別

データ検索は高速である必要がありますが、無造作であってはなりません。システムはスタッフが重複データの可能性を認識し、識別情報を一貫して保存し、患者、受診、支払者、施設間の関係を維持するのに役立つ必要があります。

![ヘルスケアシステムにおける患者データ詳細](/assets/healthcare/patient-detail.png)

_人口統計データ、連絡先情報、診療コンテキストが構造化されたプロファイルに保存されます。_

### 実際に使われる電子カルテ（RME）

RME とは、コンピュータに移された PDF アーカイブではありません。そこには診察記録、診断、アレルギー、処置、臨床観察、処方、検査結果、データ変更履歴が含まれます。

最大の課題は、できるだけ多くの列を追加することではありません。課題は、医師が診察時間を長くすることなく完全に記録できるようにすることです。そのため、フォームの構造、情報の順序、アクセス権、臨床テンプレートをユーザーと一緒に設計する必要があります。

![Codevertaヘルスケアプラットフォーム上の電子カルテ](/assets/healthcare/rekam-medis-elektronik.png)

_RME は紙のカルテの単なる代替ではなく、診療のコンテキストの中心となります。_

![患者の診療履歴を一画面で表示](/assets/healthcare/patient-history.png)

_紐づいた履歴により、医療従事者は前回の受診で何があったかを把握できます。_

### 医師のワークフローと部門間連携

医師には簡潔なサマリーが必要です：本日の患者、待ち状況、未レビューの検査結果、フォローアップが必要な処置。運用チームには異なる視点が必要です。システムは両方を提供し、新しいデータのコピーを作成しないようにする必要があります。

_連携したスケジューリングは、スケジュールの競合や不要な待ち時間を減らすのに役立ちます。_

## SATUSEHAT 統合は API コールのかなり前から始まる

SATUSEHAT は、保健省が標準化と RME 統合を通じて医療情報システムを接続するための公式プラットフォームです。データ交換にはグローバルスタンダードの HL7 FHIR を使用します。保健省は、パートナー/ベンダーの RME を使用する施設と、独自の RME を開発する施設でフローを区別しています。

技術的には API ドキュメントが重要です。しかし統合はエンドポイントから始まるわけではありません。統合は施設内のデータ品質から始まります。

受診を送信する前に、システムは正しい患者、医療サービスを提供する医療従事者、サービスを提供する組織と場所、受診の日時、診断、観察、処方された医薬品を把握している必要があります。ソースデータが一貫していなければ、API 接続が成功しても良い相互運用性は得られません。

![国家医療データ相互運用性のイラスト](/assets/healthcare/editorial/satusehat-interoperability-indonesia.png)

_編集イラスト：クリニック、病院、検査室、薬局が安全な相互運用性レイヤーを通じてデータを交換します。_

統合作業において、Codeverta は現場のイベントを交換可能なデータ構造に変換する支援を行います。例えば：

- 患者識別情報は`Patient`リソースにマッピング；
- 医療従事者と施設は`Practitioner`、`Organization`、`Location`を通じてマッピング；
- 登録と受診の経過は`Encounter`として記録；
- 診断と臨床症状は`Condition`を使用；
- 検査結果とバイタルサインは`Observation`として送信；
- 処方と薬剤払出しは`MedicationRequest`や`MedicationDispense`などのリソースを使用。

外来診療において、SATUSEHAT のドキュメントは保健省のマスターパテントインデックスからの IHS 番号の使用も規定しています。薬剤サービスにおいては、処方データ、薬剤払出しデータ、受診更新のフローが含まれます。つまり、統合は「すべてを送信」する単一のボタンではなく、診療コンテキストに従った一連のトランザクションです。

技術リファレンスは常に公式ドキュメント、例えば [SATUSEHAT 外来プレイブック](https://satusehat.kemkes.go.id/platform/docs/id/interoperability/rme-rawat-jalan/)、[薬剤サービスプレイブック](https://satusehat.kemkes.go.id/platform/docs/id/interoperability/kefarmasian/)、[施設登録ガイド](https://satusehat.kemkes.go.id/platform/docs/id/registration-guide/regis-institution/)に従います。

重要な注意：Codeverta は SATUSEHAT の所有者や管理者ではありません。同プラットフォームは保健省によって管理されています。私たちは医療施設や RME システム管理者が、このエコシステムに接続するために必要なアプリケーション、データ、統合プロセス、テスト、モニタリングを準備する支援を行います。

## RME だけではない：病院の運用も連携が必要

医療サービスは医師の机で終わるわけではありません。検査室、薬局、在庫、機器メンテナンス、部屋スケジューリング、財務、そして同様に重要な管理業務があります。

### 検査室

検査依頼は、同じ患者識別情報と受診情報を使用して、適切なユニットに届く必要があります。結果が検証された後、医師は物理的な書類や個人メッセージを待たずに確認できなければなりません。

![ヘルスケアシステムの検査モジュール](/assets/healthcare/lab-test-investigation.png)

_検査依頼と結果は患者の受診に紐づいたままです。_

### 処方、薬局、在庫

デジタル処方は単なる薬剤リストではありません。システムは用量、用法、交付ステータス、在庫、ロット、有効期限を処理する必要があります。臨床データと在庫データは異なる要件を持ちますが、両者は同じプロセスで出会います。

_薬局取引は在庫と連携し、薬剤の移動が二重に記録されないようにします。_

_Stock ageing は、長期保管アイテムや使用期限が近いアイテムをチームが把握するのに役立ちます。_

### 資産とメンテナンス

医療機器は単に棚卸資産として登録されるだけでは不十分です。校正スケジュール、メンテナンス、故障、責任者、実施記録が文書化される必要があります。

## 目に見えないが決定的なインフラストラクチャ

ユーザーはフォーム、テーブル、ダッシュボードを見ます。その背後には同等に重要な仕事があります：

- 医師、看護師、薬剤師、会計、管理者のロールベースのアクセス制御；
- 重要なデータ変更を追跡可能にする監査証跡；
- 統合キューに入る前のデータバリデーション；
- 外部サービスが利用不可の場合のリトライメカニズム；
- 障害調査のための API 応答の記録；
- 開発環境、サンドボックス、本番環境の分離；
- バックアップ、モニタリング、サービス復旧手順；
- コンテキストとユーザーの権限に応じた個人データ保護。

特に SATUSEHAT 統合において、HTTP ステータス 200 や 201 だけが成功の尺度ではありません。チームはどのリソースが送信済みか、どれが拒否されたか、なぜ拒否されたか、そして修正がデータ重複を起こさず安全に行えるかを把握する必要があります。

保健省は正常に送信された RME データを確認するためのモニタリングダッシュボードを提供しています。アプリケーション側では、施設チームが問題発生時に推測する必要がないよう、記録と運用モニタリングツールを補完しています。

![ヘルスケアプラットフォームにおける運用課題リスト](/assets/healthcare/issues.png)

_課題とフォローアップは、運用の他の部分と同様に記録される必要があり、個人的な会話で失われてはなりません。_

## 私たちの実装アプローチ

各施設には異なる習慣、規模、準備レベルがあります。そのため、実装はアプリケーションをインストールしてアカウントを渡すだけのように扱いません。

通常、作業はいくつかの段階で進みます。

**第一に、実際に発生しているフローをマッピングすること。** 私たちはデータの旅を、受付、診療、サポート部門、薬局、会計、レポート作成まで追跡します。SOP には存在するが現場では起こらないプロセスは、早い段階で区別する必要があります。

**第二に、マスターデータを整理すること。** 患者識別情報、医療従事者、場所、ユニット、サービス、医薬品、臨床用語を、移行または統合の前に確認します。これは地味な作業ですが、影響は大きいです。

**第三に、モジュールを段階的に構築すること。** 施設チームはまず中核フローを試すことができます。医師、看護師、受付スタッフ、薬剤師からのフィードバックをシステムの改善に活用します。

**第四に、相互運用性を準備すること。** FHIR マッピング、認証、バリデーション、サンドボックステスト、エラー処理、モニタリングを関連する SATUSEHAT プレイブックに従って設定します。

**第五に、稼働開始を支援すること。** 最初の数週間は小さな問題に迅速に対処する必要があります。バグではなく、混乱を招く用語や、診療のリズムに合わないボタンの順序である場合もあります。

このアプローチは確かに耳を傾けることが多くなります。ヘルスケアにおいては、それはまさに必須です。

## 私たちが求める成功の尺度

私たちは「すべてのプロセスが 10 倍速くなる」といった約束には慎重です。医療施設は複雑すぎて、一つの数字に集約できません。

より合理的な尺度は、感じられ、確認できることです：

- スタッフが患者識別情報を何度も入力しなくなる；
- 医師が多くのアプリケーションを開かずに重要な履歴を見つけられる；
- 検査結果と処方が正しい受診に紐づく；
- 薬剤チームが在庫移動のトレースを持てる；
- 経営陣が同じデータソースからレポートを取得できる；
- 統合チームが送信ステータスを確認し、エラーを修正できる；
- 施設が保健省の基準に従うための基盤をより整えられる。

優れたデジタル化は、使われていると平凡に感じられることがよくあります。待ち行列が動き、データが見つかり、処方が届き、検査結果が表示され、レポートが生成されます。テクノロジーのショーはありません。システムがただ機能するだけです。

## インドネシアのデジタルヘルスケアを構築する、使えるシステムを一つずつ

国家医療変革には SATUSEHAT のような大きなプラットフォームが必要です。しかし、国家プラットフォームは依然として、質の高いデータを生成できる病院、クリニック、検査室、薬局、その他の施設にある何千ものシステムを必要とします。

その領域で Codeverta は活動しています。

私たちは医療施設がユーザーニーズに近い運用システムを構築し、同時に保健省の方向性に沿ったデータ構造と統合インフラストラクチャを準備する支援をします。目的は単に API 接続に合格することではありません。目的は、患者ケアを妨げることなくデータが正しく流れるようにすることです。

もしあなたの施設が RME を準備中、クリニックや病院のシステムを見直している、薬局や検査室を連携させたい、または SATUSEHAT 統合を計画しているなら、Codeverta はプロセスマッピングから実装、技術支援まで支援できます。

なぜなら、結局のところ、優れたヘルスケアテクノロジーとは、最も話題になるものではありません。優れたテクノロジーとは、医療従事者が人間をケアするための時間をより多く持てるようにするものだからです。
