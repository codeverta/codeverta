# Codeverta 与印尼医疗数字化：从电子病历到 SATUSEHAT 集成

医疗数字化的话题中，人们常以为当一家诊所停止使用纸张，工作就完成了。但现实远非如此简单。

将表单转为屏幕确实属于过程的一部分。然而，更艰巨的工作出现在之后：确保患者数据不重复，医生和护士的工作流程依然顺畅，药品库存与处方相连，检验结果归入正确的病史，以及规定数据能够发送至国家生态系统。

正是在这里，Codeverta 扮演了角色。我们帮助构建医疗机构每天使用的技术层，涵盖诊所和医院管理系统、电子病历、药房、检验科、医护人员排班，乃至与 SATUSEHAT 集成的前期准备。

我们的角色很明确。印尼卫生部构建 SATUSEHAT 作为国家健康数据交换平台。Codeverta 则在设施和运营系统端工作：让日常服务中产生的数据变得整洁、结构化、安全，并准备好按卫生部规定进行交换。

## 问题不仅仅是“还没有应用程序”

在许多医疗机构中，应用程序其实早已存在。挂号用一套系统，门诊用另一套，检验科有自己的记录，而药房和收费仍依赖电子表格。每个部门都能运转，但数据并不总是使用同一种语言沟通。

后果不难预料：

- 患者需要重复提供已经给过的信息；
- 工作人员需要从一个屏幕向另一个屏幕抄录信息；
- 医生不能及时看到检查结果；
- 系统里的药品库存与货架上的不一致；
- 管理报表需要多次对账才能完成；
- IT 团队难以为了互操作性需求准备数据。

我们启动医疗项目时，第一个问题不是“想要什么功能？”。第一个问题通常更简单：从患者到达至离开，谁在做什么，哪些数据发生变化，以及流程中最容易卡顿的环节在哪里。

这些问题的答案成为了系统的基础。

## 打下基础：统一流程、单一患者病史

一个优秀的医疗系统不应让人感觉像是一堆菜单。它必须跟随患者的就诊路径。

当患者挂号时，系统创建或找到正确的身份。当患者进入诊室时，医生看到相关病史。当医生开具处方或检查申请时，药房和检验科无需重新输入即可收到数据。服务结束后，临床信息和交易仍然关联到同一次就诊。

我们将这一原则应用于多个层次。

### 挂号与患者身份

数据搜索必须快速，但不能马虎。系统需要帮助工作人员识别可能重复的数据，一致地保存身份信息，并维护患者、就诊、担保人及机构之间的关系。

![医疗系统中的患者详细信息](/assets/healthcare/patient-detail.png)

_人口学信息、联系方式及服务背景均存储于结构化的档案中。_

### 真正投入使用的电子病历

电子病历不只是转移到电脑上的 PDF 归档。它包含检查记录、诊断、过敏史、操作、临床观察、处方、辅助检查结果以及数据变更轨迹。

最大的挑战不是增加尽可能多的字段。挑战在于让医生能够完整地记录，而不延长问诊时间。因此，表单结构、信息顺序、访问权限以及临床模板需要与用户共同设计。

_电子病历是服务的核心上下文，而非仅仅是纸质病历的替代品。_

### 医生工作流与科室间协作

医生需要简洁的摘要：今日患者、候诊状态、未审阅的检查结果以及需要跟进的操作。运营团队则需要不同的视角。系统必须同时提供两者，而无需创建新的数据副本。

## SATUSEHAT 集成远在调用 API 之前就开始

SATUSEHAT 是印尼卫生部建立的官方平台，通过标准化和电子病历集成来连接健康信息系统。其数据交换采用全球标准 HL7 FHIR。印尼卫生部还区分了使用第三方/供应商电子病历的机构和自行开发电子病历的机构。

技术上，API 文档固然重要。但集成并非始于端点。集成始于机构内部的数据质量。

在一条就诊记录可以被发送之前，系统必须知道正确的患者、提供服务的医护人员、服务组织和地点、就诊时间、诊断、观察到所开具的药物。如果源数据不一致，即使 API 连接成功，也无法产生良好的互操作性。

![国家健康数据互操作性插图](/assets/healthcare/editorial/satusehat-interoperability-indonesia.png)

_编辑插图：诊所、医院、检验科及药房通过安全的互操作层交换数据。_

在集成工作中，Codeverta 帮助将现场事件转化为可交换的数据结构。例如：

- 患者身份映射到`Patient`资源；
- 医护人员和机构通过`Practitioner`、`Organization`和`Location`映射；
- 挂号及就诊轨迹记录为`Encounter`；
- 诊断和临床主诉可使用`Condition`；
- 检查结果和生命体征作为`Observation`发送；
- 处方和药品发放使用`MedicationRequest`和`MedicationDispense`等资源。

对于门诊，SATUSEHAT 文档还规定了使用卫生部主患者索引中的患者 IHS 号码。在药学服务中，流程涵盖处方数据、药品发放和就诊更新。这意味着集成并非一键“全部发送”，而是一系列遵循服务上下文的交易。

技术参考始终遵循官方文档，包括[SATUSEHAT 门诊操作手册](https://satusehat.kemkes.go.id/platform/docs/id/interoperability/rme-rawat-jalan/)、[药学服务操作手册](https://satusehat.kemkes.go.id/platform/docs/id/interoperability/kefarmasian/)以及[机构注册指南](https://satusehat.kemkes.go.id/platform/docs/id/registration-guide/regis-institution/)。

重要提示：Codeverta 并非 SATUSEHAT 的所有者或管理者。该平台由印尼卫生部管理。我们帮助医疗机构和电子病历系统管理者准备用于接入该生态系统的应用程序、数据、集成流程、测试及监控。

## 不仅仅是电子病历：医院运营也必须连通

医疗服务不止于医生诊桌。还有检验科、药房、库存、设备维护、手术室排班、财务以及同样重要的行政工作。

### 检验科

检查申请需要到达正确的科室，使用相同的患者和就诊身份。结果验证后，医生无需等待纸质文件或个人消息即可查看。

电子处方不仅仅是药品列表。系统需要处理剂量、用法、发放状态、库存、批次乃至有效期。临床数据与库存数据有不同的需求，但它们在同一流程中相遇。

## 隐形却关键的底层基础设施

用户看到的是表单、表格和仪表板。背后还有同样重要的工作：

- 基于角色的访问控制，供医生、护士、药房、收费员及管理员使用；
- 审计追踪，以便追溯重要数据的更改；
- 数据验证，在进入集成队列之前进行；
- 外部服务不可用时的重试机制；
- API 响应记录，以辅助排查故障；
- 开发、沙箱及生产环境分离；
- 备份、监控及服务恢复流程；
- 根据上下文和用户权限保护个人数据。

针对 SATUSEHAT 集成，HTTP 状态码 200 或 201 并非衡量成功的唯一标准。团队还需要知道哪些资源已经发送、哪些被拒绝、拒绝原因，以及修复是否安全而不造成重复数据。

印尼卫生部提供了监控仪表板，用于查看已成功发送的电子病历数据。在应用端，我们通过日志记录和运营监控工具来补充这一需求，以便机构团队在出现问题时无需猜测。

## 我们的实施方式

每个机构都有自己的习惯、规模及准备程度。因此，我们对待实施的方式并非安装应用程序然后交付账号。

通常工作分几个阶段进行。

**首先，绘制实际发生的流程。** 我们追踪数据从挂号、服务、辅助检查、药房、支付到报表的路径。那些仅存在于标准操作流程中、但现场并未发生的流程需要从一开始就区分开。

**其次，清理主数据。** 患者身份、医护人员、地点、科室、服务项目、药品及临床术语在迁移或集成之前进行核查。这是一项默默无闻但影响巨大的工作。

**第三，逐步构建模块。** 机构团队可以首先试用核心流程。来自医生、护士、挂号员及药房人员的反馈用于改进系统的工作方式。

**第四，准备互操作性。** FHIR 映射、身份验证、验证、沙箱测试、错误处理及监控均按照相关的 SATUSEHAT 操作手册来构建。

**第五，支持上线。** 在最初几周，需要快速处理小问题。有时不是错误，而是令人困惑的术语或不符合服务节奏的按钮顺序。

这种方法确实需要更多地倾听。对于医疗领域来说，这恰恰是必要的。

## 我们追求的成功标准

对于“所有流程快十倍”之类的承诺，我们持谨慎态度。医疗机构过于复杂，无法用一个数字来概括。

更合理的衡量标准是可感知、可验证的事项：

- 工作人员不再重复输入患者身份；
- 医生无需打开多个应用程序即可找到重要病史；
- 检验结果和处方关联到正确的就诊；
- 药房团队拥有库存移动的轨迹；
- 管理层从同一数据源获得报表；
- 集成团队可查看发送状态并修复错误；
- 机构拥有更扎实的基础来遵循卫生部标准。

好的数字化在投入使用后常常让人感觉稀松平常。队列在移动、数据被找到、处方到达、检查结果可见、报表自动生成。没有技术表演。系统只是在好好工作。

## 建设印尼数字医疗，从一个可用的系统开始

国家医疗转型需要像 SATUSEHAT 这样的大型平台。然而，国家平台仍需要成千上万的医院、诊所、检验科、药房及其他机构中的系统能够产生高质量的数据。

正是在这个空间里，Codeverta 发挥作用。

我们帮助医疗机构建立贴近用户需求的运营系统，同时准备符合印尼卫生主管部门方向的数据结构和集成基础设施。目标并非仅仅通过 API 连接测试。目标是让数据正确流动，而不干扰对患者的服务。

如果您的机构正在准备电子病历、整修诊所或医院系统、连接药房与检验科，或者计划与 SATUSEHAT 集成，Codeverta 可以提供从流程梳理到实施和技术支持的一站式帮助。

因为归根结底，好的医疗技术并非最引人瞩目的那个。好的技术是让医护人员有更多时间来照顾人的技术。
